# env-contract

Проверяет ключи `.env` по `.env.example`, не выводя значения. Python 3.11+, без зависимостей во время работы.

```sh
git clone https://github.com/dan2076-hub/env-contract.git
cd env-contract
python -m pip install .
env-contract examples/sample.env --example examples/sample.env.example
env-contract .env --example .env.example --strict --json
```

Из исходников: `python -m env_contract` с теми же аргументами. Путь к фактическому файлу обязателен; шаблон по умолчанию — `.env.example`.

Отсутствующие и пустые обязательные ключи, дубликаты в любом файле приводят к ошибке. Лишние ключи — предупреждение, а с `--strict` — ошибка. Пустые значения в шаблоне не делают ключи необязательными.

Поддерживаются UTF-8 с BOM, CRLF, `export`, однострочные кавычки и комментарии. В значении без кавычек `#` начинает комментарий после пробела. Переменные и команды не исполняются и не раскрываются. Многострочные значения не поддерживаются. Диагностика содержит имена ключей и номера строк, но не значения или исходные строки.

При ошибке синтаксиса сравнение ключей подавляется, а из ошибочного файла сохраняются только номера неверных строк: текст после незакрытой кавычки может быть частью секрета, даже если похож на отдельный ключ.

Коды завершения: `0` — принято, `1` — нарушение контракта, `2` — ошибка файла, кодировки, синтаксиса или аргументов. `--json` возвращает один JSON-объект; ошибки аргументов выводятся обычным сообщением argparse.

Файлы не изменяются, сетевых запросов нет. Это проверка набора ключей, а не сканер секретов и не полноценный shell-парсер.

Тесты: `python -m unittest discover -s tests -v`. Подробности и JSON-схема — в [README.md](README.md). Лицензия MIT.
